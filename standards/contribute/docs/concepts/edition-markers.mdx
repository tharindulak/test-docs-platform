An Edition is one choice in a Doc space's version dropdown: its Cloud docs, or one self-hosted version. An Edition marker limits a page, a section or a phrase to some Editions. Each Edition is built on its own. Content marked for other Editions is removed before the page is built, so it never reaches the table of contents or search.

## How it works

The main line of a Content repository holds the Cloud docs. When a self-hosted version reaches code freeze, its branch, such as `identity-server/release/7.4.0`, is cut from `main`. The branch is a plain copy: markers survive the cut, so the same marker decides what each branch shows:

| Marker | Cloud | Self-hosted 7.3.0 | Self-hosted 7.4.0 |
|---|---|---|---|
| `only="cloud"` | Shown | Hidden | Hidden |
| `only="self-hosted"` | Shown, labelled Self-hosted | Shown | Shown |
| `only="self-hosted" selfHostedFrom="next"` | Hidden | Hidden | Hidden |
| `selfHostedFrom="7.4.0"` | Shown | Hidden | Shown |
| `selfHostedFrom="next"` | Shown | Hidden | Hidden |

`next` means no release is committed yet. Content marked `next` stays out of every version until its release owner gives it one.

## Self-hosted additions and Edition variants

Self-hosted-only content comes in two kinds, and Cloud treats them differently:

- **A Self-hosted addition** has no Cloud counterpart, such as a page on clustering. Cloud shows it too, labelled **Self-hosted** with a link to see it in the newest release: a box around a block, and a badge under a page's title. In Cloud it reads as the newest release reads it, so its `{edition.*}` variables take the `self-hosted:` values, and `{edition.version}` is the newest release. Content in no release yet, such as `selfHostedFrom="next"`, stays out of Cloud. A Self-hosted-only page shown in Cloud has its canonical on the same page under `/latest/`. Write links in it as usual: a link Cloud cannot follow, to a page Cloud leaves out or to a heading only the Self-hosted form of a `<Variants>` has, goes to the same page under `/latest/` in Cloud.
- **An Edition variant** is one block written once for Cloud and once for Self-hosted, such as the same step in the Console and in the Management Console. Wrap the two forms in `<Variants>`, and each Edition, Cloud included, shows only its own form:

  ```mdx
  <Variants>
  <Edition only="cloud">
  Open the Console.
  </Edition>
  <Edition only="self-hosted">
  Open the Management Console.
  </Edition>
  </Variants>
  ```

  `<Variants>` holds exactly one `<Edition only="cloud">` and one `<Edition only="self-hosted">`, and nothing else.

A whole Self-hosted-only page with a Cloud counterpart names it in front matter, `cloudCounterpart: guides/cloud-billing`. It then stays out of Cloud, and the version dropdown maps the two pages to each other. Every other Self-hosted-only page shows in Cloud.

In Markdown twins and `llms.txt`, a Self-hosted addition shown in Cloud has a `**Self-hosted only.**` line before it. These rules apply where the Doc space has self-hosted versions; a family-level Doc space such as Identity Platform Cloud has none.

## After a Branch cut

A Branch cut, made with `npx @wso2/docs branch-cut <doc space> <version>` or by creating the branch on GitHub, does two things besides the branch:

- **It removes the markers the new version covers from `main`.** A `selfHostedFrom` marker of that version or an older one no longer limits anything on `main`, because every later version is cut from `main` too. `<Edition selfHostedFrom="7.4.0">` is unwrapped into plain shared content, `only="self-hosted" selfHostedFrom="7.4.0"` keeps only `only="self-hosted"`, and a page's `selfHostedFrom: 7.4.0` line goes. The change is a commit on its own branch, `branch-cut/<doc space>/<version>`, for a pull request to `main`. When the branch is created on GitHub, the Docs workflow opens that pull request itself, as a draft: its checks start when an owner marks it **Ready for review**. The release branch keeps its markers.
- **It writes the branch cut report.** The report lists what is still `next`, what ships in the version, what is held for a later version, and every marker change on `main`. Content still marked `next` stays out of the new version. The release owner decides on each `next` block: to ship it, change `next` to the version on the release branch and remove the marker on `main`; to hold it, leave it.

Markers for newer versions, `next`, Cloud only and Self-hosted only markers stay on `main` as they are. See [Add and release a Self-hosted version](../guides/product-teams/add-a-version.mdx).

## Variables

`{edition.*}` variables, such as `{edition.productName}` and `{edition.consoleUrl}`, are filled in from the Content repository's `editions.yaml`: its `cloud:` block for Cloud, and its `self-hosted:` block for every version and for Self-hosted additions shown in Cloud. `{edition.version}` is always defined.

## Limits

- Markers can't be nested inside a sentence across lines; keep inline markers on one line.
- Markers work in pages and partials. In front matter, `{edition.*}` variables work only in `title`, `sidebar_label` and `description`.
