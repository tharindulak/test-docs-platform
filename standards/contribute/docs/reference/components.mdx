WSO2 Docs pages are Markdown with a few Platform components and a page layout chosen in front matter. Content repositories hold no code: every component and layout lives in the Platform, is documented here and is open to every team.

## Page layouts

A page's `type` says what kind of writing it is (its [page type](../concepts/page-types.mdx)); its `layout` says how it is drawn. Set it in front matter; the default is `default`.

| Layout | Draws | Data |
|---|---|---|
| [`default`](#layout-default) | The page as written | none |
| [`overview`](#layout-overview) | A page of cards that link to components or sections: family-level homes, product homes, guide indexes | none (the page's own Markdown) |
| [`catalog`](#layout-catalog) | The page's text, then a searchable, filterable grid of the items in its data file, such as connectors.yaml: each with a logo, its name linked to its page, a description and more links | catalog (schemas/catalog.schema.json): categories (the filter chips) and items (id, name, description, href, links, category, tags, logo, status, editions) |
| [`api-reference`](#layout-api-reference) | An API reference page rendered from its OpenAPI spec, with its own navigation, operations and samples | the OpenAPI spec (synced from the product repository by the spec-sync workflow) |
| [`complete-guide, sdk, connector`](#layout-complete-guide) | The migration's page templates, drawn as default | none |

### default {#layout-default}

The page as written. Every page has it unless it says otherwise.

- **Data:** none
- **Markdown form:** The page.
- **Accessibility:** The theme's article, TOC and sidebar.
- **Owner:** docs-platform · **Since:** first map

```yaml
layout: default
```

### overview {#layout-overview}

A page of cards that link to components or sections: family-level homes, product homes, guide indexes. Every H2 or H3 section that holds only text and links, with a list or a paragraph that is one link, becomes a card; cards in a row share a grid, and text after a card's links labels the next row. Everything else stays prose, and the page has no TOC column.

- **Data:** none (the page's own Markdown)
- **Markdown form:** The page as written.
- **Accessibility:** Cards are sections headed by the page's headings; see OverviewCard.
- **Owner:** docs-platform · **Since:** Extension points in the Platform

```mdx
---
layout: overview
---
## Get started
- [Create an account](./get-started/create-an-account.mdx)
- [Connect a React app](./get-started/react.mdx)
```

### catalog {#layout-catalog}

The page's text, then a searchable, filterable grid of the items in its data file, such as connectors.yaml: each with a logo, its name linked to its page, a description and more links. Items can be limited to Editions, and the page has no TOC column.

- **Data:** catalog (schemas/catalog.schema.json): categories (the filter chips) and items (id, name, description, href, links, category, tags, logo, status, editions)
- **Markdown form:** The page's text, then the items as a list; see Catalog.
- **Accessibility:** See Catalog.
- **Owner:** docs-platform · **Since:** Extension points in the Platform

```yaml
layout: catalog
data: ./connectors.yaml
```

### api-reference {#layout-api-reference}

An API reference page rendered from its OpenAPI spec, with its own navigation, operations and samples.

- **Data:** the OpenAPI spec (synced from the product repository by the spec-sync workflow)
- **Markdown form:** The overview, then the operations from the spec.
- **Accessibility:** See the API components.
- **Owner:** docs-platform · **Since:** first map (API reference rendering)

```yaml
layout: api-reference
spec: ./openapi.yaml
```

### complete-guide, sdk, connector {#layout-complete-guide}

The migration's page templates, drawn as default. A folder of complete-guide pages is also exported as one Markdown file.

- **Data:** none
- **Markdown form:** The page (a complete guide also joins its folder's single export).
- **Accessibility:** As default.
- **Owner:** docs-platform · **Since:** first map (MkDocs migration)

```yaml
layout: complete-guide
```

## Data files

A layout that draws data reads a YAML or JSON file committed next to the page, generated upstream (the product's CI) and synced by a bot pull request, never by a script in the build. The [data files check](checks.mdx#data-files) validates each one against its Platform schema on every pull request and release.

| Kind | Schema | Found |
|---|---|---|
| `catalog` | `schemas/catalog.schema.json` | named by a catalog page's `data:` front matter |
| `release-notes` | `schemas/release-notes.schema.json` | by name: release-notes.yaml (or .yml, .json) anywhere in docs/ |
| `sdks` | `schemas/sdks.schema.json` | by name: sdks.yaml (or .yml, .json) anywhere in docs/ |

### Edition {#edition}

Limits a block or a phrase to some Editions (an Edition marker). The build removes what the Edition does not show; previews outline it.

- **Use:** Writers use it
- **Markdown form:** The content, when the Edition shows it; nothing otherwise.
- **Accessibility:** Adds no markup to a published page. In previews (EditionMarker) the label is text, not colour alone.
- **Owner:** docs-platform · **Since:** first map (Edition markers)

```mdx
<Edition only="self-hosted">Restart the server.</Edition>
```

### Variants {#variants}

An Edition variant: one block written once for Cloud and once for Self-hosted, as exactly one `<Edition only="cloud">` and one `<Edition only="self-hosted">`. Each Edition, Cloud included, shows only its own form. Without it, Cloud would also show the Self-hosted form, as a Self-hosted addition.

- **Use:** Writers use it
- **Markdown form:** The Edition's own form only; nothing marks the other.
- **Accessibility:** Adds no markup to a published page. In previews each form is outlined and labelled as an Edition variant (EditionMarker).
- **Owner:** docs-platform · **Since:** Cloud Edition content

```mdx
<Variants>
<Edition only="cloud">
Open the Console.
</Edition>
<Edition only="self-hosted">
Open the Management Console at `https://localhost:9443/console`.
</Edition>
</Variants>
```

### SelfHostedAddition {#selfhostedaddition}

A Self-hosted addition shown in Cloud: Self-hosted-only content (an `<Edition only="self-hosted">` block or phrase, or an `editions: self-hosted` page) with no Cloud counterpart. Labelled "Self-hosted", with a link "See it in" the newest release (such as Identity Server 7.3.0) to the same page under `/latest/`: a box around a block, a badge under a page's title.

- **Use:** Generated by the Platform
- **Markdown form:** A `**Self-hosted only.**` line before the block, or under the page's title; `**Self-hosted only:**` in front of a phrase. The page's llms.txt entry starts with `**Self-hosted only.**`.
- **Accessibility:** The label is text ("Self-hosted"), never colour alone; a block is a labelled section (aria-label "Self-hosted only"), and the link names the release it opens.
- **Owner:** docs-platform · **Since:** Cloud Edition content

### Anchor {#anchor}

A link target that is not a heading, for migrated `<a name>` anchors. Links to it are checked like links to headings.

- **Use:** Written by the migration
- **Markdown form:** Nothing (the target has no text).
- **Accessibility:** An empty span with an id; nothing to read or focus.
- **Owner:** docs-platform · **Since:** first map (MkDocs migration)

```mdx
<Anchor id="configure-the-keystore" />
```

### DocsLink {#docslink}

A link to another Docs deployment, made from a `docs:<space>/<edition>/<page>` Markdown link. It opens as a full page load in the same tab.

- **Use:** Generated by the Platform
- **Markdown form:** A Markdown link to the target page's address.
- **Accessibility:** A plain link with its own text; it never opens a new tab.
- **Owner:** docs-platform · **Since:** first map (docs links)

### a (FileLink) {#a}

Every link in page content. Links to files the build emits keep their address (no trailing slash added).

- **Use:** Generated by the Platform
- **Markdown form:** A Markdown link.
- **Accessibility:** The theme's link, unchanged.
- **Owner:** docs-platform · **Since:** first map (API reference rendering)

### EditionMarker {#editionmarker}

Previews only (show-markers mode). Outlines a marked block and labels it, for the Edition toggle.

- **Use:** Generated by the Platform
- **Markdown form:** The content in the Edition it is active in (twins are exported without markers).
- **Accessibility:** The label is text, and inactive blocks are faded but still readable.
- **Owner:** docs-platform · **Since:** first map (Edition markers)

### PageActions {#pageactions}

The "Copy page" menu next to the title (copy or view the Markdown twin, open it in an AI assistant).

- **Use:** Generated by the Platform
- **Markdown form:** Nothing (it is the twin's own menu).
- **Accessibility:** A button with a menu, keyboard operable, with its state announced (aria-expanded).
- **Owner:** docs-platform · **Since:** first map (AI/LLM-friendly docs)

### ApiReference, ApiNav, ApiContent, ApiHeader, ApiTag, ApiOperation, ApiOperationMain, ApiSamples, ApiMethod, ApiEndpoint, ApiDetails, ApiSchema, ApiCode {#apireference}

The parts of an API reference page, generated from its OpenAPI spec by the api-reference layout.

- **Use:** Generated by the Platform
- **Markdown form:** None of their own; an API page's twin lists the operations from the spec (lib/api-twin.mjs).
- **Accessibility:** Method badges meet WCAG 2.2 AA in both themes (test/api-reference.test.mjs); headings per tag and operation; schemas in native details elements.
- **Owner:** docs-platform · **Since:** first map (API reference rendering)

### OverviewGrid, OverviewCard {#overviewgrid}

The cards of the overview layout, drawn from the page's own sections.

- **Use:** Generated by the Platform
- **Markdown form:** The sections as written (the twin is the page's Markdown).
- **Accessibility:** Each card is a section headed by the page's own heading, so the outline, anchors and TOC data stay as written; card text uses the chrome's checked colour pairs (test/contrast.test.mjs).
- **Owner:** docs-platform · **Since:** Extension points in the Platform

### Catalog, CatalogItem, CatalogLogo {#catalog}

The searchable grid of the catalog layout, drawn from the page's data file.

- **Use:** Generated by the Platform
- **Markdown form:** A list of the items shown in the Edition, each with its name linked, its status, its description and its other links. Logos are left out.
- **Accessibility:** Every item is in the server-rendered list; the search box has a label, the filter chips are buttons with aria-pressed in a labelled group, the result count is announced (role="status"), hidden items leave the reading order, and logos are decorative (alt="", the name is text). Checked by test/build.test.mjs and the nightly axe run.
- **Owner:** docs-platform · **Since:** Extension points in the Platform

### ThemedImage {#themedimage}

An image with one file per colour theme, for screenshots taken in both: readers see the one matching their theme. `light` and `dark` are literal paths (relative ones are bundled like Markdown images), and `alt` describes both. Without `dark`, the light image shows in both themes. The theme's own `sources={{ light: '…', dark: '…' }}` form still works, imported from `@theme/ThemedImage`.

- **Use:** Writers use it
- **Markdown form:** The light image, with its alt text.
- **Accessibility:** One `alt` for both images, required like any image's; both are server-rendered and the theme hides the other. The build checks both files exist (test/build.test.mjs).
- **Owner:** docs-platform · **Since:** Integrator on the proof (Docusaurus-source conversion)
- **Import from:** `@theme/ThemedImage` (the only module ids a page may import)

```mdx
<ThemedImage light="../../assets/img/flow-light.png" dark="../../assets/img/flow-dark.png" alt="The flow designer with a new HTTP service" />
```

### Tabs, TabItem, Details, Admonition, CodeBlock, Mermaid, DocCardList, Head, TOCInline {#tabs}

The Docusaurus theme components WSO2 content uses (admonitions are usually written with `:::note`).

- **Use:** Writers use it
- **Markdown form:** Tabs become labelled sub-sections, Details is expanded, admonitions become `> **Note:**`, code stays code, DocCardList lists the folder's pages, Head and TOCInline leave nothing.
- **Accessibility:** The Docusaurus theme's own (keyboard tabs, native details).
- **Owner:** docs-platform · **Since:** first map (Docusaurus theme)
- **Import from:** `@theme/Tabs`, `@theme/TabItem`, `@theme/Details`, `@theme/Admonition`, `@theme/CodeBlock`, `@theme/Mermaid`, `@theme/DocCardList`, `@docusaurus/Head`, `@theme/TOCInline` (the only module ids a page may import)

## Propose a component or layout {#propose}

A team that needs something the Platform does not have proposes it; there is no escape hatch (no code, raw HTML widgets or per-team CSS, and iframes only from the hosts in `standards/iframe-hosts.yaml`; the [content safety check](checks.mdx#content-safety) enforces it). Until it ships, link out.

1. Open an [extension proposal](https://github.com/wso2/docs-platform/issues/new?template=extension-proposal.yml) in the Platform repository: what it is, which pages need it, and why the existing components and layouts do not fit.
2. Once the Platform team agrees, open a pull request to the Platform. Your team may be its first user.
3. To join this catalogue it needs a generic name (no product's), a Markdown form, an accessibility check, its entry here and an owner.
4. It ships in a Platform release and is open to every team. Manifest and data-file fields are only ever added.
