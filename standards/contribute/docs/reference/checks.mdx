## MDX compile {#compile}

Every page and partial compiles through the Platform's MDX pipeline, in each Edition it renders in.

- **Check ID:** `compile`
- **Blocks the pull request**. The Docs release build runs it again.

**How to fix it:** Read the error's line and column. Common causes are a bare `<` or `{` in prose (put it in `code`) and an unclosed JSX tag.

## Preview build {#preview-build}

The affected Edition builds with broken links, anchors and images set to fail.

- **Check ID:** `preview-build`
- **Blocks the pull request**. The Docs release build runs it again.

**How to fix it:** Fix the link, anchor or image path named in the error. Links between pages are relative file paths (`../guides/mfa.mdx#choose-a-factor`).

## Links to other Doc spaces {#docs-links}

Every `docs:` link names a Doc space and Edition in the deployment manifest, and its page (and anchor) is in that deployment's published route list.

- **Check ID:** `docs-links`
- **Blocks the pull request**. The Docs release build runs it again.

**How to fix it:** Check the target page's URL on WSO2 Docs and copy its path after the Edition: `docs:<space>/<edition|latest>/<page>/`.

## Doc space manifest {#manifest}

The Doc space manifest (`docspace.yaml`) follows its schema and composes with the published Deployment manifest: its home section lists it, its Cloud parts point both ways, its branches, pins and notices name what exists. The same rules as the compose check on the pull request.

- **Check ID:** `manifest`
- **Blocks the pull request**.

**How to fix it:** Fix the field the message names. `home-not-listing` clears once the home section's team lists the Doc space (that change merges first). Every error is described in the developer guide's Manifest checks reference.

## Release branch scope {#release-scope}

A change to a Doc space's release branch (`<doc space>/release/<version>`) touches only that Doc space's directory. The branch is a copy of the whole repo, but it builds only its own directory.

- **Check ID:** `release-scope`
- **Blocks the pull request**.

**How to fix it:** Move the change to the right branch: another Doc space's pages go to its own branches, and shared root files change on `main`.

## Redirect coverage {#redirects}

A page removed or moved in this change has a `moves:` entry in `redirects.yaml` pointing at a page that exists.

- **Check ID:** `redirects`
- **Blocks the pull request**, and a Doc space owner can override it.

**How to fix it:** Add `- from: <old path>` and `to: <new path>` under `moves:` in `redirects.yaml`. For a removed page, point it at the closest remaining page.

## Front matter {#front-matter}

Every page has a title, a description of at most 160 characters and a page type, uses only known keys, and has valid Edition values.

- **Check ID:** `front-matter`
- **Blocks the pull request**. The Docs release build runs it again.

**How to fix it:** Copy the front matter of the page-type template (`wso2-docs new <type>`), then fill it in.

## Data files {#data-files}

Every data file a page draws (`data:` on a `layout: catalog` page) and every data file known by its name (`release-notes.yaml`, `sdks.yaml`) follows its Platform schema: catalog, release notes or SDK list. Ids are unique, categories are listed, and links and logos point at pages and assets that exist.

- **Check ID:** `data-files`
- **Blocks the pull request**. The Docs release build runs it again.

**How to fix it:** Fix the field the message names. A generated file is fixed where it is generated (the product's CI), then synced again by its bot PR; the schemas are in the Platform's `schemas/` folder, and editors validate against them.

## Edition markers and variables {#markers}

Every `<Edition>` marker is valid and every `{edition.*}` variable is defined in `editions.yaml` for each Edition the content renders in.

- **Check ID:** `markers`
- **Blocks the pull request**. The Docs release build runs it again.

**How to fix it:** Use `only="cloud"`, `only="self-hosted"` or `selfHostedFrom="<version>|next"`, and define the variable in the `cloud:` or `self-hosted:` block of `editions.yaml`.

## Marker versions {#marker-versions}

A new or changed `selfHostedFrom` version on the main line is newer than the latest released version in the deployment manifest.

- **Check ID:** `marker-versions`
- **Blocks the pull request**, and a Doc space owner can override it.

**How to fix it:** Content already in the latest release needs no marker; content for an unannounced release uses `selfHostedFrom="next"`.

## Folder skeleton {#skeleton}

Top-level `docs/` folders follow the sidebar skeleton: get-started, guides, concepts, reference, deploy-and-operate, release-notes. In a Doc space with `audienceGroups`, only the groups sit at the top, and the skeleton folders sit inside each group.

- **Check ID:** `skeleton`
- **Blocks the pull request**. The Docs release build runs it again.

**How to fix it:** Move the folder under one of the skeleton folders; add sections below the top level only.

## Image size {#image-size}

A new or changed image is at most 1 MB (warns over 300 KB). A Content repository over 1 GB warns.

- **Check ID:** `image-size`
- **Blocks the pull request**, and a Doc space owner can override it.

**How to fix it:** Crop to the relevant UI and save as PNG or WebP; most screenshots fit in 300 KB.

## Image alt text {#image-alt}

A new image reference has alt text that says what the image shows.

- **Check ID:** `image-alt`
- **Blocks the pull request**.

**How to fix it:** Write what the reader would miss without the image, for example `![The Applications page with the New application button](...)`.

## OpenAPI specs {#openapi}

Every API page's OpenAPI spec validates (structure, broken `$ref`s, duplicate operation IDs). Description style on changed specs only warns.

- **Check ID:** `openapi`
- **Blocks the pull request**. The Docs release build runs it again.

**How to fix it:** Run `npx @wso2/docs api validate` and `npx @wso2/docs api lint` for the full list, and fix the spec where it is synced from (the product repository).

## Content safety {#content-safety}

Content carries no code. Pages import only from the component catalogue (`standards/components.yaml`) and relative `.mdx` partials inside the Doc space, and export nothing; `{…}` holds only literals and `require()` of a file inside the Doc space; no `.js`, `.jsx`, `.ts`, `.tsx`, `.mjs` or `.cjs` file, `<script>`, `on*=` attribute, `javascript:` URL or `dangerouslySetInnerHTML`; an `<iframe>` only from the hosts in `standards/iframe-hosts.yaml`, with no `srcdoc`, and no `<object>`, `<embed>` or `<frame>`. It breaks the build: no override. Bundles run it again, and so does intake.

- **Check ID:** `content-safety`
- **Blocks the pull request**. The Docs release build runs it again.

**How to fix it:** Remove the code. Use a Platform component instead (see Components and layouts), write the value as a literal, and embed videos from `https://www.youtube-nocookie.com/embed/<id>`. What content needs beyond this goes through an extension proposal.

## Markdown twins {#twins}

Each page's Markdown twin has no leftover JSX or imports, and its links resolve.

- **Check ID:** `twins`
- **Blocks the pull request**. The Docs release build runs it again.

**How to fix it:** Every Platform MDX component declares a Markdown form; a leftover component here is a Platform bug, so report it.

## Prose style (Vale) {#vale}

The WSO2 Vale style on changed lines. Product-name rules are at error level but don't block until cutover.

- **Check ID:** `vale`
- **Warns only**.

**How to fix it:** Follow the message; each one links to its rule in the style guide.

## Spelling (cspell) {#spelling}

US English spelling on changed lines, with the Platform dictionaries plus the repository's `words.txt`.

- **Check ID:** `spelling`
- **Warns only**.

**How to fix it:** Fix the typo, or add a correct product or technical term to `words.txt` (one word per line).

## Headings and house style {#headings}

On changed lines: no skipped heading levels, a language on every code fence and no `$` prompts. Admonitions use the five types, at most two in a row, and link text is descriptive.

- **Check ID:** `headings`
- **Warns only**.

**How to fix it:** Follow the message; each one links to the rule in the style guide.
