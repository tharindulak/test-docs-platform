This page lists every workflow in `wso2/docs-platform`'s `.github/workflows/`, and the ones a Content repository carries from `templates/content-repo/`. Production jobs run only when the variable `DOCS_PRODUCTION_ENABLED` is `true`, which it isn't for the Pilot.

## Release and compose

| Workflow | File | Trigger | What it does | Needs |
|---|---|---|---|---|
| Intake | `intake.yml` | At minutes 7 and 37 of every hour; by hand, with an optional `repo` or `space` (a run by hand tries a failed tag again) | Composes the manifest, reads every Content repository's releases, verifies each one that counts (digest, attestation, safe unpacking, `bundle.json`, `content-safety`), writes `releases/<slug>.yaml`; then opens or updates one pull request per Doc space on `intake/<slug>` with auto-merge on, and one `bundle-intake` issue per Doc space and tag for a failure or a withdrawal | `DOCS_INTAKE_APP_ID`, `DOCS_INTAKE_APP_KEY` (the App that opens the pull requests); `DOCS_BUNDLE_SIGNER_REPO` (optional); `CONTENT_READ_TOKEN` while Content repositories are private; **Allow auto-merge** on, and **CI**'s `intake-record` required on `main` |
| Release docs | `release.yml` | A merge to `main` that changes `releases/*.yaml` (an intake pull request); by hand with `scope` `docspace` (and `space`), `all` or `landing`; **Platform deployments** (Contribute's Cloud tags with `repo` and `tag`, scope `landing`); the **Platform release** workflow (scope `all`: the Docs deployments whose Content repository pins its major). Content repositories dispatch nothing. | Composes and stores the manifest, plans from the intake records, builds each Docs deployment from its recorded bundle, uploads each build in a separate job, flips staging (back, for a withdrawn release), writes the redirect table, runs the crawl gate, indexes search, keeps the last 5 releases; promotes to production when the crawl passed | Staging and production environments: R2, Cloudflare and Typesense credentials, in the jobs that run no content code; `CONTENT_READ_TOKEN` |
| Build one Docs deployment | `build-deployment.yml` | Called by Release docs, once per Docs deployment | Fetches the recorded bundle, checks its sha256 against the intake record and unpacks it (the Platform's own Doc space: checks out the tag), builds the Doc space's directory with the stored manifest and staging's deployment state (so its menus list only deployed Doc spaces), runs `wso2-release check` and `wso2-docs check --release`, and hands the build to Release docs' publish job as an artifact. It runs bundle content, so it has no environment and no storage credential. | `DOCS_BUILD_RUNNER` (optional), `SEARCH_KEY_STAGING`, `SEARCH_KEY_PRODUCTION` (repository variables); `CONTENT_READ_TOKEN`, in the download step only |
| Manifests | `manifests.yml` | A merge to `main` that changes `navigation/`, `schemas/` or Contribute's `docspace.yaml`; by hand | Composes every Content repository's `main` and stores it, republishes the runtime files, starts a `docspace` rebuild for each Doc space whose Editions or `latest` changed; production republishes staging's copy | Staging and production environments; `CONTENT_READ_TOKEN` |
| Compose check | `compose-check.yml` | A pull request that changes `navigation/`, `schemas/`, Contribute's `docspace.yaml` or the compose code | Composes `main` as the base, then the pull request on top; blocks on errors in the files it changes | `CONTENT_READ_TOKEN`, only to clone |
| Platform release | `platform-release.yml` | A pushed `v<major>.<minor>.<patch>` tag on `main` or `releases/v<major>` | Checks the tag against `package.json`, the branch and **CI**; publishes `@wso2/docs` to npm; moves the `v<major>` tag when it is the newest release of the major; makes the GitHub release; starts **Release docs** with scope `all` at the tag | The `npm` environment, trusted by `@wso2/docs` on npmjs.com; no secrets |
| Platform deployments | `platform-deployments.yml` | A merge to `main` that changes what Contribute's build reads, or `navigation/` or `chrome/landing.yaml`; by hand (releases both) | For Contribute, makes the next Cloud tag on the Platform repository and starts **Release docs** for it; for the Landing deployment, starts **Release docs** with scope `landing` | Nothing: the workflow token |
| Roll back docs | `rollback.yml` | By hand, with `deployments`, `to` (optional) and `environment` | Points each Docs deployment back, republishes the runtime files, writes the redirect table, repairs the search index | The chosen environment's credentials |

## Edge and search

| Workflow | File | Trigger | What it does | Needs |
|---|---|---|---|---|
| Edge Worker | `edge.yml` | A merge to `main` that changes `worker/`; by hand | Runs the Worker's tests, then deploys `worker/` to staging, and to production when it is on. Skipped until `CLOUDFLARE_ACCOUNT_ID` is set. | `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN` |
| Search consistency | `search-consistency.yml` | Mondays at 03:17 UTC, with repair; by hand, with `fix` | Compares each environment's collection with every live Docs deployment, and repairs drift | R2 and Typesense credentials per environment |

## Checks and reports

| Workflow | File | Trigger | What it does | Needs |
|---|---|---|---|---|
| CI | `ci.yml` | Every pull request, and every merge to `main` or a `releases/v<major>` branch, in the Platform | The test suite, the workflow lint and the Edge Worker bundles for both environments. On pull requests, `intake-record`: an `intake/<slug>` branch changes only the release entries of `releases/<slug>.yaml`; on other branches, every changed record is valid. | Nothing |
| Docs PR preview build | `pr-preview.yml` | Called by a Content repository's `docs.yml`, once per Doc space a pull request touches | `wso2-docs check` on the Doc space's directory, with its strict build of the Edition, and `wso2-docs bundle --dry-run`; then a second build with `--show-markers`, uploaded as `docs-preview-<doc space>` (the checked build if that one fails) | No secrets, so pull requests from forks are safe |
| Docs PR preview publish | `pr-preview-publish.yml` | Called by a Content repository's `docs-preview-publish.yml` | Validates each preview build and publishes it to `<staging-host>/_preview/<doc space>/pr-<n>/<edition>/`, then comments the link | The Content repository's previews credential and `R2_ENDPOINT` |
| Docs bundle | `docs-bundle.yml` | Called by a Content repository's `docs.yml` with a Docs release tag, from its `release` and `release-tag` jobs | Checks out the Platform at `v1` and the Content repository at the tag; runs `wso2-docs check --release --no-lint` and `wso2-docs bundle`; attests `<slug>-<tag without its prefix>.docs.zip` with build provenance and publishes it as the tag's GitHub Release, with its sha256 and source commit in the notes, never latest or a pre-release | `contents: write`, `id-token: write`, `attestations: write` from the caller; `DOCS_PLATFORM_READ_TOKEN` while the Platform is private |
| Docs AI review | `pr-review.yml` | Called by `docs.yml` when `DOCS_AI_REVIEW_ENABLED` is `true` (off until cutover) | Runs the "Check my changes" skill and comments on the pull request | `ANTHROPIC_API_KEY`, `CONTENT_READ_TOKEN` in the Content repository |
| Docs branch cut | `branch-cut.yml` | Called by a Content repository's `docs.yml` when a release branch is created | Runs `wso2-docs branch-cut --branch` on the new branch, pushes `branch-cut/<doc space>/<version>` and opens its pull request on `main` with the branch cut report; does nothing if that branch exists already | The Platform's GitHub App on the Content repository (`DOCS_PLATFORM_APP_ID`, `DOCS_PLATFORM_APP_KEY`) |
| Spec sync | `spec-sync.yml` | Called by a Content repository's `docs-sync.yml` | Copies an OpenAPI spec from a product repository and opens or updates one pull request | `product_repo_token` for a private product repository |
| Nightly docs reports | `nightly-reports.yml` | Every night at 02:30 UTC; by hand | Full crawl with external links, axe checks, lint counts per Content repository. Its search step is a placeholder: the weekly Search consistency workflow does that check. | `CONTENT_READ_TOKEN`; `DOCS_REPORT_HOST` (optional) |
| Weekly docs digest | `weekly-digest.yml` | Mondays at 06:00 UTC; by hand | Helpfulness, searches with no results, top 404s and new issues, per Doc space | `CLOUDFLARE_ANALYTICS_TOKEN`, `TYPESENSE_ANALYTICS_KEY`, `CLOUDFLARE_ACCOUNT_ID`, `TYPESENSE_HOST` |

## In a Content repository

| Workflow | File | Trigger | What it does |
|---|---|---|---|
| Docs | `docs.yml` | Pull requests to `main`, `release/**` and `*/release/**`; merges to `main`; Docs release tags pushed by hand; **Run workflow** with a Doc space and a version; a created release branch | Plans the Doc spaces an event touches (`wso2-docs spaces`), runs the preview build and checks per Doc space and the compose check, sums them up as **preview / checks**; on a merge or **Release docs**, makes the next tag and calls the Platform's **Docs bundle** with it (a tag pushed by hand too); on a created release branch, calls the Platform's branch cut |
| Docs preview publish | `docs-preview-publish.yml` | When a **Docs** run of a pull request finishes | Calls the Platform's preview publish with the repository's previews credential |
| Docs sync | `docs-sync.yml` | By hand; optionally on a schedule | Calls the Platform's spec sync for generated content. Optional. |

## Concurrency groups

Jobs that write an environment's published state have no group: each command waits its turn on the bucket's state lock instead, so none is cancelled. See [The release pipeline](../../concepts/platform-team/release-pipeline.mdx#who-runs-at-once).

| Group | Who shares it | What it does |
|---|---|---|
| `intake` | Intake runs | One at a time; a poll that finds one running waits |
| `release-records-<commit>` | The release a merged intake record change starts | One per merge |
| `release-<repo>-cloud` | The Platform's own Cloud releases (Contribute) | A newer run cancels the one in progress |
| `release-<repo>-<tag>`, `release-platform-<space or scope>` | Other releases and rebuilds, such as `release-platform-landing` | One at a time per group |
| `docs-tag-contribute` | Contribute's tag making in **Platform deployments** | One at a time |
| `edge-worker` | Edge Worker deploys | One at a time |
| `platform-release` | Platform releases | One at a time |
| `docs-tag-<doc space>` | Tag making in a Content repository | One at a time per Doc space |
