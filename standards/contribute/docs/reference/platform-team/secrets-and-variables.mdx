This page lists every secret and variable the workflows read, where it is set, and what reads it. Nothing here is set yet: the values come with hosting.

## The Platform repository

GitHub environments `staging` and `production` hold the credentials for each environment's bucket, redirect table and search collection. Jobs that write to an environment run in it. A job that builds a Docs bundle runs no environment and holds none of them: it hands its build to a job that uploads it.

| Name | Kind | Where | Read by | Value |
|---|---|---|---|---|
| `R2_ENDPOINT` | Variable | Each environment | Every job that reads or writes a bucket | `<r2-endpoint>`, the account's S3 API address |
| `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` | Secret | Each environment | The same jobs | A credential that can write that environment's bucket |
| `CLOUDFLARE_ACCOUNT_ID` | Variable | Each environment | Edge Worker, redirect table, weekly digest | `<cloudflare-account>` |
| `CLOUDFLARE_API_TOKEN` | Secret | Each environment | Edge Worker deploy, redirect table | A token that can deploy Workers and write that environment's KV namespace |
| `REDIRECTS_KV_ID` | Variable | Each environment | Release docs, Roll back docs | `<redirects-kv-id>`, the environment's KV namespace |
| `DOCS_SEARCH_HOST` | Secret | Each environment | Release docs, Roll back docs, Search consistency | The search host's SSH address. For staging, `141.148.145.173`, the 141 VM. |
| `DOCS_SEARCH_KNOWN_HOSTS` | Secret | Each environment | The same | The search host's `known_hosts` line, from `ssh-keyscan -t ed25519`, checked against the host's own fingerprint |
| `DOCS_SEARCH_UPLOAD_KEY` | Secret | Each environment | The same | The private half of the upload key: it can only write search files into the host's incoming folder |
| `DOCS_SEARCH_GATE_KEY` | Secret | Each environment | The same | The private half of the gate key: it can only run the gate's search verbs. The Typesense admin key never leaves the host. |
| `CONTENT_READ_TOKEN` | Secret | Repository | Every job that clones Content repositories; Intake, to read releases; a build's bundle download | A read-only token for every Content repository, while they are private |
| `DOCS_INTAKE_APP_ID` | Variable | Repository | Intake, its `propose` job | The GitHub App that pushes `intake/<slug>` and opens its pull request, with **Contents** and **Pull requests** set to read and write on this repository. A pull request the workflow token opens starts no checks, so it would never merge. |
| `DOCS_INTAKE_APP_KEY` | Secret | Repository | The same | The App's private key |
| `DOCS_BUNDLE_SIGNER_REPO` | Variable, optional | Repository | Intake | The repository whose `.github/workflows/docs-bundle.yml` at `refs/tags/v1` signs the bundles. Default: this repository. |
| `SEARCH_KEY_STAGING`, `SEARCH_KEY_PRODUCTION` | Variable | Repository | Build one Docs deployment | Scoped search-only browser keys, from the gate's `search-key`. Public by design. |
| `DOCS_PRODUCTION_ENABLED` | Variable | Repository | Every production job | `true` turns production on. Unset for the Pilot. |
| `DOCS_BUILD_RUNNER` | Variable, optional | Repository | Build one Docs deployment | A larger runner's label. Default `ubuntu-latest`. |
| `DOCS_REPORT_HOST` | Variable, optional | Repository | Nightly docs reports | The host to report on. Default `<staging-host>`. |
| `CLOUDFLARE_ANALYTICS_TOKEN`, `TYPESENSE_ANALYTICS_KEY` | Secret | Repository | Weekly docs digest | Read tokens for feedback and search analytics |
| `TYPESENSE_HOST` | Variable | Repository | Weekly docs digest | The search host to read analytics from |

The Edge Worker has one secret of its own, `TYPESENSE_SEARCH_KEY`, a search-only key for the MCP endpoint, set with `wrangler secret put` per environment. It is not the browser key: the gate's `search-key --expires <date>` makes it (see [Make the Edge Worker's key](../../guides/platform-team/run-the-search-index.mdx#make-the-edge-workers-key)).

### Intake's pull requests

An intake pull request merges by itself, so set these once on `wso2/docs-platform`:

| What | Where | Value |
|---|---|---|
| Allow auto-merge | **Settings** > **General** > **Pull Requests** | On |
| A ruleset on `main` with required checks | **Settings** > **Rules** | **CI**'s `intake-record` and `test`, with no one allowed to bypass. Intake's App then merges nothing that changes more than release entries. |
| Required reviews | A second ruleset on `main` | Keep reviews for everyone else, with the intake App as the only bypass, so its pull requests need no review |
| Automatically delete head branches | **Settings** > **General** | On, so a merged `intake/<slug>` goes away |

### npm

The **Platform release** workflow publishes `@wso2/docs` with npm's trusted publishing, so no npm token is stored as a secret. Set it up once:

| What | Where | Value |
|---|---|---|
| The `npm` environment | `wso2/docs-platform` > **Settings** > **Environments** | No secrets. Add required reviewers to approve each publish, if you want. |
| A trusted publisher | The `@wso2/docs` package on npmjs.com > **Settings** > **Trusted publishing** | GitHub Actions: organization `wso2`, repository `docs-platform`, workflow `platform-release.yml`, environment `npm` |
| Tag rulesets | `wso2/docs-platform`, if a ruleset protects `v*` tags | GitHub Actions may bypass it, so the workflow can move the `v1` tag |

npm adds provenance to each version once `wso2/docs-platform` is public.

## Content repositories

Each Content repository sets these. `init` and the converter write the workflows that read them.

| Name | Kind | Read by | Value |
|---|---|---|---|
| `DOCS_PLATFORM_READ_TOKEN` | Secret | `docs.yml`, to check out the Platform | A read-only token for `wso2/docs-platform`, while it is private |
| `DOCS_PREVIEW_R2_ACCESS_KEY_ID`, `DOCS_PREVIEW_R2_SECRET_ACCESS_KEY` | Secret | `docs-preview-publish.yml` | A credential that can write only the previews bucket |
| `R2_ENDPOINT` | Variable | `docs-preview-publish.yml` | `<r2-endpoint>` |
| `DOCS_PUBLISHED_MANIFEST` | Variable, optional | `docs.yml`, compose job | The published manifest to compose against. Default `https://<staging-host>/manifest.json`. |
| `DOCS_AI_REVIEW_ENABLED` | Variable, optional | `docs.yml` | `true` turns the AI review on. Off until cutover. |
| `ANTHROPIC_API_KEY`, `CONTENT_READ_TOKEN` | Secret, optional | `pr-review.yml`, with the AI review on | The review's model key, and the read token for cloning |

The Branch cut job needs no secret: it pushes its branch and opens its draft pull request with the workflow token. It needs **Allow GitHub Actions to create and approve pull requests** turned on in the repository's **Settings** > **Actions** > **General**.

## Hosting values

These are placeholders on the Platform team's pages. The code assumes the interim values below until the Cloudflare deploy runbook sets the real ones.

| Placeholder | What it is | Interim value in the code | Where it is set |
|---|---|---|---|
| `<production-host>` | The production host | `docs.wso2.com` | `worker/wrangler.jsonc` (`DOCS_HOST`, routes), canonicals (`--site-url`) |
| `<staging-host>` | The staging host | `docs-staging.wso2.com` | `worker/wrangler.jsonc`; `STAGING_HOST` in `release.yml`; `lib/published.mjs` (`DEFAULT_PUBLISHED`); `pr-preview.yml` and `pr-preview-publish.yml`; `templates/content-repo/.github/workflows/docs.yml` |
| `<search-staging-host>` | Staging's search endpoints, on the 141 VM | `https://141-148-145-173.sslip.io/_typesense` | `lib/search/environments.mjs`, `worker/wrangler.jsonc` (`TYPESENSE_HOST`), `setup.sh apply --host` in `hosting/vm/` |
| `<search-production-host>` | Production's Typesense | `search.docs.wso2.com` | `lib/search/environments.mjs` |
| `<cloudflare-account>` | The Cloudflare account | none | `CLOUDFLARE_ACCOUNT_ID` |
| `<redirects-kv-id>` | Each environment's KV namespace | `PENDING_INFRA_STAGING_REDIRECTS_KV_ID`, `PENDING_INFRA_PRODUCTION_REDIRECTS_KV_ID` | `worker/wrangler.jsonc`, `REDIRECTS_KV_ID` |
| `<r2-endpoint>` | The account's R2 S3 API address | none | `R2_ENDPOINT` |
| Buckets | Release storage per environment, and previews | `docs-staging`, `docs-prod`, `docs-previews` | `worker/wrangler.jsonc`, the workflows' `--storage` |
