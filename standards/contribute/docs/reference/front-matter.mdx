Front matter is the YAML block between `---` lines at the top of a page. The front-matter check fails on a missing required key, a wrong value or an unknown key.

```yaml
---
title: Add multi-factor authentication
description: Require a second factor when users sign in to your application.
type: how-to
---
```

## Keys

| Key | Required | Value | Description |
|---|---|---|---|
| `title` | Yes | string | The page title, in sentence case. It is the H1 and the browser title. |
| `description` | Yes | string, at most 160 characters | One sentence of at most 160 characters, used by search, cards and SEO. |
| `type` | Yes, or from the folder | one of `quick-start`, `tutorial`, `how-to`, `concept`, `reference`, `release-notes` | The page type. May be left out where the skeleton folder sets a default. |
| `sidebar_label` | No | string | A shorter label for the sidebar, in sentence case. |
| `sidebar_position` | No | number | Order within the folder's sidebar group. |
| `editions` | No | `cloud` or `self-hosted` | Limits the page to `cloud` or `self-hosted` (an Edition marker for the whole page). |
| `selfHostedFrom` | No | an exact version such as `7.4.0`, or `next` | The first self-hosted version that has this page, or `next`. |
| `cloudCounterpart` | No | string | Self-hosted-only pages (`editions: self-hosted`): the Cloud page that covers the same task, as its path in docs/, such as `guides/cloud-billing`. The page then stays out of Cloud, and the version dropdown maps the two pages to each other. Without it, Cloud shows the page labelled Self-hosted. |
| `layout` | No | `default`, `overview`, `catalog`, `api-reference`, `complete-guide`, `sdk`, `connector` | How the page is drawn, independently of its page type: `default`, `overview` (its sections of links become cards), `catalog` (a searchable grid of the items in its `data` file) or `api-reference` (an OpenAPI spec). `complete-guide`, `sdk` and `connector` come from the migration and are drawn as `default`. See the component catalogue. |
| `data` | No | string | Catalog pages (`layout: catalog`): the data file the grid shows, next to the page, such as `./connectors.yaml` (schema: catalog). |
| `spec` | No | string | API pages (`layout: api-reference`): the OpenAPI file, such as `./openapi.yaml`. |
| `server` | No | string | API pages only. The base URL shown in examples; `{edition.*}` variables work here. |
| `tag` | No | string | API pages only. Makes this page one tag of a large API. |
| `slug` | Discouraged | string | Discouraged. The folder path is the URL, and slugs are permanent. |
| `keywords` | No | a list of strings | Extra search keywords. |
| `hide_table_of_contents` | No | boolean | Hides the table of contents on the right. |
| `toc_max_heading_level` | No | number | The deepest heading level in the table of contents (2 to 6). |
| `unlisted` | No | boolean | Builds the page without a sidebar entry or search listing (pages that were outside the legacy nav). |

## Default page type by folder

| Folder | Default type |
|---|---|
| `get-started/` | `quick-start` |
| `guides/` | `how-to` |
| `concepts/` | `concept` |
| `reference/` | `reference` |
| `deploy-and-operate/` | `how-to` |
| `release-notes/` | `release-notes` |
