# AI and LLM outputs

Last checked against code: 2026-10-27

What WSO2 Docs offers AI agents and LLM tools.

## Markdown twins

- **Every page has a Markdown twin at its address with `.md`** (`…/guides/mfa/` → `…/guides/mfa.md`, a home page at `index.md`), generated by a Platform remark step from the Edition's resolved MDX: markers applied, variables filled, partials inlined, components in their Markdown form, links pointing at other twins, and front matter with title, description, Edition and canonical URL. [F21] [F32]
- **Every Platform MDX component must declare a Markdown form**, or Platform CI fails. The blocking twins check requires resolving links and no leftover JSX. [F21] [F32]
- **An API page's twin holds its overview, the YAML download link and a compact operation list.** The operations are not rendered as prose. [F21] [F32]
- **A folder with `customProps: { export: single }` in its `_category_.yml` gets one joined `<folder>.md`** in sidebar order (Docusaurus rejects a top-level `export:`), and its index twin moves to `<folder>/index.md`. [F21] [F32]

## `llms.txt`

| File | Contents |
|---|---|
| `docs.wso2.com/llms.txt` | Written at flip time from the manifest: every Doc space, steering to `/latest/` and `/cloud/`, plus Cloud parts as "<Component> Cloud" and Contribute; end-of-life Editions and Doc spaces not on WSO2 Docs yet left out |
| `<doc-space>/<edition>/llms.txt` | Every page of the Edition, grouped by the sidebar, with `.md` links and descriptions, and every API's YAML |
| `<doc-space>/<edition>/llms-full.txt` | Every page's Markdown, in sidebar order |

[F21] [F32] [N17]

- **Labels follow the chrome** ("(newest release)" / "(latest)"; see [editions-and-versions.md](editions-and-versions.md#order-and-labels)). [N04] [N21]

## Page actions

- **A "Copy page" menu after the title offers Copy as Markdown, View as Markdown, and Open in Claude / ChatGPT** (a chat whose prompt cites the `.md` URL). It is one chrome component, added without a swizzle; API pages don't get it. [F21] [F32]

## MCP server

- **A read-only MCP endpoint at `docs.wso2.com/mcp`, part of the Edge Worker**, with three tools: `search_docs(query, docSpace?, edition?)` on the same index and scope rules, `get_page(url)` returning the twin, and `list_editions(docSpace?)` from the manifest. Its tool descriptions use the chrome's words: an all-Doc-spaces search covers each Doc space where its selector opens (Cloud, else its newest release). It runs on staging only during the Pilot (`MCP_ENABLED`). [F21] [F32] [N20]

## Out of scope

- **There is no on-site AI chat and no AI answers in search.** That needs an LLM backend, retrieval, cost controls and a data and safety policy, and is its own product decision; the twins, `llms.txt` and the MCP server are its base. [F21] [F-map]
