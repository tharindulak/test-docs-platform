# AI and LLM outputs

Last checked against code: 2026-10-27

What WSO2 Docs offers AI agents and LLM tools.

## Markdown twins

- **Every page has a Markdown twin at its address with `.md`** (`…/guides/mfa/` → `…/guides/mfa.md`, a home page at `index.md`), generated by a Platform remark step from the Edition's resolved MDX: markers applied, variables filled, partials inlined, components in their Markdown form, links pointing at other twins, and front matter with title, description, Edition and canonical URL. [F21] [F32]
- **Each of the page's own headings ends in `{#id}`, the id the page gives it**, so an anchor of the page finds its heading in the twin. The exporter takes it as Docusaurus does, after the Platform's remark steps and once per file: an explicit id (`{#id}`, `{/* #id */}`), else the heading's text slugged and numbered when repeated, a partial's headings numbered on their own. Headings the twin adds (a tab's label, a title) carry none. `get_page` finds a `section` by these ids only. A twin built before headings carried ids has none at all; until its Edition is built again, `get_page` finds its sections by their headings' text, slugged as the site does, so explicit ids aren't found there.
- **Every Platform MDX component must declare a Markdown form**, or Platform CI fails. The blocking twins check requires resolving links and no leftover JSX. [F21] [F32]
- **An API page's twin holds its overview, the YAML download link and a compact operation list.** The operations are not rendered as prose. [F21] [F32]
- **A folder with `customProps: { export: single }` in its `_category_.yml` gets one joined `<folder>.md`** in sidebar order (Docusaurus rejects a top-level `export:`), and its index twin moves to `<folder>/index.md`. [F21] [F32]

## `llms.txt`

| File | Contents |
|---|---|
| `docs.wso2.com/llms.txt` | Written at flip time from the manifest: every Doc space, steering to `/latest/` and `/cloud/`, plus Cloud parts as "<Component> Cloud" and Contribute; end-of-life Editions and Doc spaces not on WSO2 Docs yet left out |
| `<doc-space>/<edition>/llms.txt` | Every page of the Edition, grouped by the sidebar, with `.md` links and descriptions, and every API's YAML |
| `<doc-space>/<edition>/llms-full.txt` | Every page's Markdown, in sidebar order |

- **Labels follow the chrome** ("(newest release)" / "(latest)"; see [editions-and-versions.md](editions-and-versions.md#order-and-labels)). [N04] [N21]

## Page actions

- **A "Copy page" menu after the title offers Copy as Markdown, View as Markdown, and Open in Claude / ChatGPT** (a chat whose prompt cites the `.md` URL). It is one chrome component, added without a swizzle; API pages don't get it. [F21] [F32]

## MCP server

- **A read-only MCP endpoint at `docs.wso2.com/mcp`, part of the Edge Worker**, with three tools. Each declares an output schema, and each answer carries a structured result that follows it, next to a short text form. Its tool descriptions use the chrome's words: an all-Doc-spaces search covers each Doc space where its selector opens (Cloud, else its newest release). It runs on staging only during the Pilot (`MCP_ENABLED`). [F21] [F32] [N20]
  - **`search_docs(query, product?, edition?, includeSelfHosted?, limit?)`** searches the same index with the same scope and ranking rules as the search box ([search.md](search.md#mcp)). `product` is a Doc space slug; `tools/list` offers the searchable ones, read from the manifest, and `docSpace` stays as its old name. It answers with up to 10 pages (5 by default), best first, each with its best section's heading, URL and text (at most 2,000 characters) and up to two more of its sections. A Cloud part's page names its family Cloud as its product. The text form gives each page's URL and Markdown URL, and each section's heading with its anchor, so a client that reads only text can still ask `get_page` for a section. The `product` choices are the manifest's when `tools/list` is called; the server checks `product` itself, and lists no choices when it can't read the manifest.
  - **`get_page(url, section?, maxChars?)`** returns the twin, or with `section` (a heading anchor, as the twin's `{#id}` names it) only that heading's section: to the next heading of the same or a higher level. Its result names the page read by its own address on the host that answered. Text past `maxChars` (20,000 by default, at most 100,000) is cut, with a note that says so. It doesn't read `llms-full.txt`, which holds a whole Edition; `llms.txt` stays readable.
  - **`list_editions(docSpace?)`** lists Doc spaces and their Editions from the manifest, listing a component's Cloud part as its Cloud Edition, as its version selector does.
- **The MCP server makes no LLM calls, uses no embedding model and logs no query text.** It sends each search in the body of a `POST /multi_search`, so no access log on the way records the query, and its searches are left out of search analytics. [F21]

## Out of scope

- **There is no on-site AI chat and no AI answers in search.** That needs an LLM backend, retrieval, cost controls and a data and safety policy, and is its own product decision; the twins, `llms.txt` and the MCP server are its base. [F21] [F-map]
